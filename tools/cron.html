📖 About This Tool

What is Cron?

Cron is a time-based job scheduler found on Unix-like systems. It runs commands automatically at fixed times, dates, or intervals — like backups, emails, reports, or CI/CD jobs.

Why do developers need it?

  • Automation — schedule tasks without manual work
  • Easy to get wrong — one wrong character = job never runs
  • Hard to read — */15 9-17 * * 1-5 is not obvious
  • Used everywhere — Linux, GitHub Actions, Jenkins, Kubernetes, AWS

The 5 Fields

  • Minute — 0 to 59
  • Hour — 0 to 23
  • Day of Month — 1 to 31
  • Month — 1 to 12 (or JAN–DEC)
  • Day of Week — 0 to 6 (Sunday = 0, or SUN–SAT)

Special Characters

  • * — every value (any)
  • , — list (e.g. 1,15,30)
  • - — range (e.g. 9-17)
  • / — step (e.g. */5 = every 5)

⚠️ The Biggest Pitfall

When both Day-of-Month and Day-of-Week are restricted (not *), cron uses OR logic, not AND.

Example: 0 0 15 * 1 means "midnight on the 15th OR every Monday" — not "midnight on the 15th if it's a Monday".

This confuses almost every developer at least once.

Where is it used?

  • Linux crontab (crontab -e)
  • GitHub Actions — on: schedule: cron:
  • Jenkins, GitLab CI
  • Kubernetes CronJob
  • AWS EventBridge, CloudWatch
  • Node.js — node-cron, cron packages

Pro tip

Always test your cron expression with a parser before deploying. A wrong character means your job either never runs or runs at the wrong time — and you might not notice for days.
